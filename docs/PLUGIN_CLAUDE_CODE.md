# bough as a Claude Code plugin

This repo doubles as a [Claude Code plugin](https://code.claude.com/docs/en/plugins.md)
so bough can be driven from inside a session instead of only from a shell.
This is separate from bough's own gRPC **engine** plugins
(`bough-plugin-<kind>`, see [`PLUGIN_AUTHOR_GUIDE.md`](./PLUGIN_AUTHOR_GUIDE.md));
"plugin" here means the Claude Code kind.

## Pick a variant

| Plugin | Ships | Command names |
|---|---|---|
| `bough` | commands + skill | `/bough:create`, `/bough:list`, … |
| `bough-hooks` | hooks | — |
| `bough-all` | commands + skill + hooks | `/bough-all:create`, `/bough-all:list`, … |

Claude Code namespaces a plugin's commands under the plugin's name, so the
same command reads `/bough:create` or `/bough-all:create` depending on the
variant. Pick `bough` + `bough-hooks` if you want the shorter names with hooks.

```text
/plugin marketplace add threecorp/bough
claude plugin install bough-all@bough --scope project   # this repo only (recommended)
claude plugin install bough-all@bough --scope user      # every repo
```

The hooks act on the monorepo the session is in, so install a variant that
carries hooks at project scope unless you want them in every repo. The
`claude plugin install` CLI defaults to user scope when `--scope` is omitted.

## What each part does

### Slash commands — you type these

| Command | What it does | Args |
|---|---|---|
| `create` | Create a worktree environment: engines up, `.env.local` rendered for repos that declare `env_local`. | `<worktree-name>` |
| `remove` | Tear one down: engines stopped, datadirs dropped, worktree removed. The branch is kept unless `teardown.remove_branch: true`. | `<name-or-path>` |
| `list` | List registered worktrees and their ports. | — |
| `status` | Registered ports and whether a listener is detected on each (uses `lsof`). | — |
| `verify` | Check a worktree's engine `main` ports and `ports:` entries against the declared ranges, and that its `.env.local` files exist. | `<name>` |
| `config-validate` | Validate `./.bough.yaml` (or a given path) against the schema. | `[path]` |
| `doctor` | Report hook wiring, worktree containers, engine plugins, and leftovers from retired features. | — |

### Skill — Claude may invoke this on its own

| Skill | What it does |
|---|---|
| `using-bough` | Guidance on which command fits the user's intent, plus a `command -v bough` preflight that stops with install guidance when the binary is missing. |

### Hooks (`bough-hooks` / `bough-all`)

Both events run `bough hook handle --event <E>`:

| Event | Effect |
|---|---|
| WorktreeCreate | run create and print the worktree root for Claude Code to `cd` into |
| WorktreeRemove | run remove |

Claude Code fires these for `claude --worktree`, for a subagent with
`isolation: "worktree"`, and for background sessions. Nothing else is
wired.

Versions up to v0.27.0 also wired `PreToolUse`, `PostToolUse`,
`UserPromptSubmit`, `Stop`, `SessionEnd` and `PreCompact`; see
[MIGRATION-v0.27-to-v0.28.md](MIGRATION-v0.27-to-v0.28.md) to clear them.

## The CLI installs the same artifacts

The commands and skill are embedded in the binary, and the hook entries are generated by it:

```text
bough claude hook install --scope project      # ./.claude/settings.json
bough claude skill install --scope project     # ./.claude/skills/
bough claude command install --scope project   # ./.claude/commands/
bough claude <kind> list | uninstall           # same verbs for all three
```

- `--scope project` means the current directory's `.claude/`, so run it
  from the monorepo root. `--scope user` means `~/.claude/`.
- Commands installed this way are not namespaced: `/create`, not
  `/bough:create`.
- `install` overwrites every file bough ships (`commands/create.md`,
  `skills/using-bough/SKILL.md`, …), including one you wrote under the
  same name. `uninstall` removes those command files and the whole
  `skills/using-bough/` directory, including any file you added inside
  it. Other files are left alone.
- `bough create` symlinks only `CLAUDE.md` into a worktree, so a worktree
  session does not see project-scoped commands or skills; install them
  user-scoped if you want them there.

## Pick one wiring for hooks, not both

`bough claude hook install` and the `bough-hooks` / `bough-all` plugins
wire the same dispatcher. Both at once fire every event twice, so one
`claude --worktree` runs create twice. `bough claude doctor` warns when
both are in the project's `settings.json`; it cannot see a plugin enabled
at user scope (`claude plugin list` shows that).

## Layout

```text
.claude-plugin/
  marketplace.json   # the catalog: bough / bough-hooks / bough-all
  plugin.json        # manifest for the root `bough` plugin
commands/            # slash commands, one .md each
skills/using-bough/  # the skill
claude-plugins/
  bough-hooks/hooks/hooks.json     # the one copy of the hook manifest
  bough-all/                       # symlinks to commands/, skills/, bough-hooks/hooks
```

`marketplace_test.go` and `internal/hooks/plugin_sync_test.go` fail
`go test` if a symlink is replaced by a copy. No `plugin.json` sets `version`,
so each plugin tracks the git commit.

## The binary is a prerequisite, not bundled

The plugins ship markdown + JSON only. Every command shells out to `bough`
on `PATH`; install it from a GitHub release or with `go install` (see the
README **Install** section).
